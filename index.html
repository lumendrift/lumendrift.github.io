The problem

AI agents can't reliably transact with most stores

Protocols are fragmented, manifests are absent, and agent traffic is treated as noise. The result: failed transactions, lost revenue, invisible regressions.

Protocol fragmentation

No two storefronts speak the same machine-readable commerce protocol. Agents stitch fragile heuristics across HTML, schema.org, and bespoke APIs.

Silent regressions

A theme update or A/B test breaks the agent flow with zero observability. You only find out when revenue drops.

Agents block themselves

Without declared identity schemes and intent endpoints, agents trigger fraud rules and rate limits — your best customers blocked first.

Validate via API

Run the same validation from CI on every deploy. Block merges on regressions.

bash
curl -X POST https://api.ucp.dev/v1/validate \
  -H "Authorization: Bearer $UCP_API_KEY" \
  -d '{"domain": "shop.example.com"}'

Standard endpoint shape

Every UCP-compliant capability returns a predictable, machine-readable shape.

GET /api/ucp/catalog
HTTP/1.1 200 OK
Content-Type: application/json
UCP-Version: 1.0
 
{
  "items": [
    { "sku": "abc-123", "title": "...", "price": 4900, "currency": "USD" }
  ],
  "next": "/api/ucp/catalog?cursor=..."
}

Sample manifest

Drop this at /.well-known/ucp.json to declare your store agent-ready.

ucp.json
 1{
 2  "version": "1.0",
 3  "store": {
 4    "name": "Example Store",
 5    "domain": "shop.example.com",
 6    "platform": "shopify"
 7  },
 8  "capabilities": {
 9    "catalog":  { "endpoint": "/api/ucp/catalog",  "methods": ["GET"] },
10    "search":   { "endpoint": "/api/ucp/search",   "methods": ["GET"] },
11    "cart":     { "endpoint": "/api/ucp/cart",     "methods": ["GET","POST","DELETE"] },
12    "checkout": { "endpoint": "/api/ucp/checkout", "methods": ["POST"] }
13  },
14  "identity": { "schemes": ["agent-token","mtls"] },
15  "payments": ["card","apple_pay","agent-wallet"],
16  "contact":  { "agent_relations": "agents@example.com" }
17}
